# FAILURE MODES — silent-failure playbook

Append every new failure with its **signature**: how you tell it apart from the others.
Most of them look identical from outside ("patch installed, nothing changed").

**Encoded:** `python -m bl2_triage` applies the discriminators below to a run's evidence and
prints the F-number and the fix (`src/bl2_triage/rules.py`; condensed text in
`src/bl2_triage/failure_modes.json`). When a new row lands here, add its rule and catalog
entry there too, or the next reader pays for the prose again.

| # | Symptom | Likely cause | Discriminator |
|---|---|---|---|
| F1 | Patch installs, edit visible when reopening the package, nothing in game | Load-order shadowing: an earlier-loaded package holds an object with the same name | Linter flags it; renaming the object fixes it |
| F2 | Nothing in game, linter clean | TFC not run, wrong mod folder, or patched the non-DLC set | Check TFC's own install log / revert state |
| F3 | Mesh appears but mangled | FBX smoothing/triangulation done at export instead of pre-applied as geometry | Re-export per brief §0.5 |
| F4 | Mesh appears, wrong material | MIC still references original texture/mesh object | Inspect MIC texture tab in UPK Explorer |
| F5 | Part never appears on any weapon | Part not in any part list collection | Linter check #4 |
| F6 | Item equipped, then vanishes on reload | Sanity check; serialization not handled | Reproduce with a save/quit/reload cycle |
| F7 | Crash on load | Package table corruption | Revert via TFC, rebuild patch from clean |
